LiarsLand · 议会模式行动动画计划

恢复撤离动画，并给倾向、投票、政治交易补齐舞台动画

当前项目里旧的行动动画层仍然存在：project/scripts/ui/action_animation_overlay.gd 已有 leave 撤离动画和青色撤离粒子资产。 问题主要在议会模式的新行动结算路径没有等待动画播放；同时新动作 retreat、declare_tendency、cast_vote、offer_trade 还没有专属视觉语言。

目标规则

所有会结束对话或推进阶段的行动，都必须先播放动画。动画完成后，才进入议会状态页、下一阶段、下一句对话或 NPC 选择页。

撤离：恢复旧 leave 倾向：公开软承诺 投票：锁票落印 交易：契约绑定

一、现状判断

撤离动画还在

ActionAnimationOverlay.play_action("leave", ...) 会隐藏 UI chrome、显示玩家/NPC 肖像、生成青色烟雾、速度线和残影，然后等待约 3.2 秒结束。

议会手动行动绕过动画

_on_manual_action_pressed 在 council_mode 分支里调用规则、刷新状态后直接返回，没有调用 _play_action_animation。

动作命名不一致

规则层使用 retreat / declare_tendency / cast_vote / offer_trade，动画层使用旧动作 leave / invite / duel / gift。需要新增议会动作映射或让 overlay 原生支持新动作。

三、流程接入方式

核心不是让动画“同时播一下”，而是把它做成行动结算后的阻塞步骤。伪流程如下：

1. 选择行动玩家点撤退、倾向、投票、交易，或 NPC JSON 返回行动。
2. 规则结算调用 CouncilRulesEngine.apply_member_action，得到事件和胜负/处决状态。
3. 播放动画await _play_council_action_animation(action, actor, payload, events)。
4. 写入 UI动画结束后追加系统日志、刷新状态面板、显示结果 banner。
5. 推进阶段如果行动结束对话，再进入议会状态页或下一名议员选择。
关键验收：撤退、正式投票、政治交易、LLM 达到对话结束条件，都不允许在 overlay 结束前调用下一阶段入口。

四、动画设计

1. 暂时撤退 / retreat

沿用旧 leave：场景压暗，玩家向左后撤，青色烟雾和速度线拉出残影，NPC 立在远端消失在暗场。最后出现“暂时撤退完成”。

节奏：0.35 秒压暗起势，1.85 秒角色离场，2.6 秒结果字出现，总长约 3.2 秒。

2. 倾向表达 / declare_tendency

发言者身前推出一圈金色声波，声波穿过中线后变成半透明议会印章。印章根据票向染色：有罪偏红，无罪偏青，弃权偏灰金。

视觉含义：这不是锁票，而是一句公开承诺。印章只半亮，最后化成灰色头像/倾向记录的粒子。

3. 直接投票 / cast_vote

一张羊皮票从行动者手边飞到屏幕中央，票面落下红/青票向符号，随后被金色圆印重重盖住。盖印时做一次短促震屏。

视觉含义：正式票不可更改。若触发处决，盖印后追加红色裂纹和更重的低频闪光；若只是普通落票，则用短金光收尾。

4. 政治交易 / offer_trade

双方各抛出一张票据，中线出现契约线，把 1 到 3 个议案串成发光节点。玩家接受后，节点依次盖印；拒绝则契约线断裂成灰尘。

视觉含义：交易是绑定票，不是单票。多议案时用 1、2、3 个节点从左到右依次亮起，最后形成一条红金青混色链。

七、实现顺序

第一步：恢复撤离动画

先只改 adventure_screen.gd，让议会手动 retreat 调用 overlay 的 leave 动画，并在 await 结束后再刷新和跳转。这个改动风险最低，能立刻验证用户感知。

第二步：补动作映射层

新增 _council_animation_action、_play_council_action_animation，避免每个调用点自己判断旧动作/新动作。

第三步：扩展 overlay

在 ACTION_DURATION 和 match normalized 中加入三种新动作；复用已有 gold_oath、red_rupture、cyan_escape、white_clash 粒子。

第四步：NPC 和交易确认接入

NPC 动作生效后播放对应动画。交易弹窗接受后播“契约成立”；拒绝时只播短断裂动画或不播完整行动动画，避免误导为已落票。

八、测试与验收

  • 运行 project/tests/action_animation_overlay_check.gd：撤离、倾向、投票、交易都能单独播放并自动隐藏。
  • 运行 project/tests/action_animation_integration_check.gd：议会手动撤退必须让 overlay 可见，并且耗时不低于撤离动画时长。
  • 补一个议会交易接受测试：接受政治交易后先播契约动画，再刷新状态页的正式票。
  • 补一个投票处决测试：正式票触发处决时，动画结果使用处决/死亡强反馈，然后再进入结果或状态页。
  • 导出网页视觉截图：至少覆盖 retreat、declare_tendency、cast_vote、offer_trade 四张关键帧。
最小可交付版本：先恢复撤离动画和等待流程。完整版本：四个议会行动都有专属动画，并且玩家/NPC 都走同一套等待逻辑。

九、执行结果
