议会四行为完整实现改进计划

基于 docs/brainstorm/council-faith-core-gameplay.html 的核心玩法方向，以及当前 Godot 原型的实际状态，目标是把“暂时撤退、倾向表达、直接投票、政治交易”完整接入玩家和 NPC 的同一套议会行为系统。

输出：实现计划 范围：玩家 + NPC 重点：四种行为完整闭环 日期：2026-05-11

一、目标状态

暂时撤退

任何一方可结束本次会谈，不产生新票，但必须进入议会状态页，让玩家观察当前公开局势。

倾向表达

任何一方可对一条罪行表达有罪、无罪或弃权倾向。倾向是公开软承诺，可被后续倾向覆盖，也会保留历史轨迹。

直接投票

任何一方可对一条罪行投出正式票。正式票公开、锁定、不可更改，并立刻检查处决阈值。

政治交易

任何一方可提出 1 到 3 个议案的绑定投票方案。玩家确认后，交易内所有合法投票同时锁定。

设计原则：四种行为必须同构。玩家角色、NPC、真实按钮、LLM 输出、测试脚本都走同一套行为解析、校验、结算和日志记录。

二、当前断点

模块 当前状态 影响 改进方向

规则引擎 已有 CouncilRulesEngine.apply_member_action、cast_vote、declare_tendency、apply_trade_offer。 规则层可跑测试，但主屏幕没有使用它。 主流程进入 council mode 后只调用 CouncilRulesEngine，暂停旧 RulesEngine 行动。
NPC 对话 Prompt 已有 council 版，但运行时仍用旧 npc_dialogue_system 和旧道具交易格式。 NPC 不会可靠地产生政治交易提案。 切到 council_npc_system_v2 / council_npc_user_v2，并新增交易确认解析。
玩家动作 左侧按钮资源存在，但没有连到实际处理函数。 玩家无法手动验证四种行为，也无法看到交易子页面。 四个会议按钮打开对应子页面；正式玩法可保留“自动玩家角色 LLM”开关。
政治交易 UI 只有旧道具交易确认弹窗。 玩家无法确认 NPC 提议的 1 到 3 个投票议案。 新增议会交易确认页，展示发起者、议案列表、双方将要投出的票、危险提示。

三、统一行为数据

新增或收敛为一个统一结构，作为 UI、LLM、测试脚本与规则引擎之间的唯一契约。

字段 类型 说明
actor_id String 行动发起者，玩家为 player，NPC 使用成员 id。
action String retreat、declare_tendency、cast_vote、offer_trade。
target_crime_id String 单议案行为使用。必须存在于本章罪行库。
vote String guilty、innocent、abstain。
bound_votes Array 政治交易使用。长度 1 到 6；对应 1 到 3 个议案，每个议案至少包含双方各一张票。
proposal_id String 交易确认用。NPC 提案先进入待确认状态，玩家接受后才落票。
speech String 对话文本。行为结算必须依赖结构化字段，不解析自然语言。
关键修正：当前 apply_trade_offer 会直接把 bound_votes 落成正式票。改进后，NPC 发起的交易必须先进入 pending_council_trade_offer，只有玩家确认后才执行。

四、行为流程

玩家发起

  1. 点击会议按钮

    打开对应子页面：撤退确认、倾向选择、投票选择、交易编辑。

  2. 选择议案

    投票和倾向选择 1 条罪行；政治交易选择 1 到 3 条罪行。

  3. 选择票向

    每条议案选择有罪、无罪或弃权。政治交易同时指定玩家票与要求 NPC 投出的票。

  4. 确认结算

    直接调用 CouncilRulesEngine.apply_member_action。交易作为玩家主动提案时可立即要求 NPC 接受或拒绝。

  5. 刷新公开记录

    状态页显示新倾向、新正式票、交易来源、处决变化和下一步入口。

NPC 发起

  1. LLM 输出结构化行为

    NPC 返回 action 与合法字段，自然语言只用于表达态度。

  2. 规则预校验

    剔除不存在罪行、已锁定票、死亡成员、危险自杀票和超出数量的交易。

  3. 交易需要确认

    NPC 的 offer_trade 不立即落票，先弹出交易确认页。

  4. 玩家接受或拒绝

    接受后双方绑定票同时结算；拒绝后记录“交易被拒绝”，不落票。

  5. 对话结束路径统一

    撤退、投票、交易、达到轮数都进入议会状态页，再回 NPC 选择页。

五、四种行为验收规格

行为 玩家实现 NPC 实现 规则验收 UI 验收
暂时撤退 点击撤退按钮后弹确认；确认后结束会谈。 NPC 可返回 retreat；系统展示 NPC 撤退文本。 不新增投票；本回合会谈结束；进入状态页。 状态页出现“本次会谈结束：某某撤退”。继续后仍有最多 3 名候选 NPC。
倾向表达 选择罪行和票向后记录玩家倾向。 NPC 可主动表达或回应玩家压力表达倾向。 同一成员同一罪行只保留最新有效倾向；历史页保留轨迹。 状态页用灰色头像显示倾向，正式投票后从倾向区移除或降为历史。
直接投票 选择罪行和票向后正式锁票。 NPC 可主动投票，但不能改已锁定票，不能对不存在罪行投票。 正式票不可更改；投票后立即检查处决和胜负。 状态页用彩色头像落到有罪或无罪列；弃权进入历史与摘要，不占有罪/无罪列。
政治交易 玩家可编辑 1 到 3 个议案，要求双方投指定票。 NPC 可提出 1 到 3 个议案，玩家确认后执行。 交易内所有合法票同源记录为 trade，同一交易原子化结算。 确认页展示议案、双方票向、危险提示、接受/拒绝；接受后状态页显示交易链。

六、政治交易细则

议案数量

每次交易允许 1 到 3 个不同罪行。重复罪行合并为一条；非法罪行直接拒绝整个提案或剔除后降级为可确认提案。

双方共同投票

每条议案必须至少包含玩家和当前 NPC 各一张正式票。可以扩展到已公开参与交易的第三方，但第一版只做双方。

原子化结算

接受交易后，先批量写入所有合法正式票，再统一检查处决，避免第一张票触发死亡后导致后续票丢失。

交易示例 结构化含义 玩家看到的文本
单议案 玩家投 C03 有罪，NPC 投 C03 有罪。 “我们一起把 C03 推到有罪。”
交换保护 玩家投 C02 无罪，NPC 投 C04 有罪。 “你保住 C02，我帮你压 C04。”
三议案套餐 C01 双方无罪，C03 双方有罪，C05 玩家弃权/NPC 有罪。 “三张票一起落，少一张都不算交易。”

玩家提议时

标题仍为“政治交易提案”，副标题改为“灰狐代笔员提出”。状态徽标显示“等待 NPC 确认”。底部主按钮对玩家不可点，显示“等待回应”；可保留“撤回提案”。

NPC 提议时

状态徽标显示“等待玩家确认”。底部提供“拒绝”和“接受并执行”。玩家接受后立即调用交易结算；拒绝只写入会谈日志。

双方同意后

弹窗切换为“交易已执行”，按钮变为“查看议会状态”。所有议案行显示落票结果，并高亮可能触发处决的罪行。

区域 内容 设计理由
标题区 交易标题、发起者台词、等待状态徽标。 玩家第一眼知道是谁提出、当前轮到谁确认。
双方身份区 左侧提议方，右侧确认方；每侧前方显示角色大头像，后方两行文字显示名字与“提议方 / 等待确认”。 同一 UI 同时支持玩家提议和 NPC 提议，只需交换头像、身份文字和按钮状态。
议案列表 最多 3 行，每行一条罪行，右侧直接显示该提案的有罪、无罪或弃权结论。 提案本身已经代表双方共同承诺，不再重复显示玩家票和 NPC 票两列。
损害标记 如果某条提案损害玩家利益，该议案整行使用红色背景，并在罪行标题旁显示“损害我”。 风险必须贴在具体提案上，而不是作为泛泛的说明文字放在弹窗底部。
底部操作 确认方看到“拒绝 / 接受并执行”；提议方看到“等待回应 / 撤回提案”。 避免玩家误以为自己能替 NPC 确认，也避免 NPC 提案绕过玩家确认。

八、实现阶段

阶段 任务 完成标准
P0 修正 council 启动路径：根据配置加载 council 章节，或建立独立 council 屏幕入口。 启动游戏后进入议会章节；状态页能显示罪行、阵营、成员和投票板。

P3 实现 NPC 政治交易确认页和待确认交易状态。 NPC 提出 1 到 3 个议案后，玩家接受才落票，拒绝不落票。
P4 完善状态页和历史页对四种行为的可视化。 玩家能区分撤退、倾向、正式票、交易票，并追踪每条票的来源。
P5 联调真实 LLM 策略，让 NPC 主动发起交易、回避危险罪行、保护阵营利益。 第一章连续 3 局至少自然出现倾向、直接投票和政治交易。

十、优先决策

建议立即确认

  • 正式 UI 是否允许真人手动点四个会议行为，还是只作为调试开关。
  • NPC 政治交易被玩家拒绝后，是否消耗本次 NPC 行动。
  • 无罪票是否只是公开立场，还是能形成“保护阈值”。第一版建议只作为公开正式票，不额外锁死法案。
  • 弃权票是否显示在状态页。第一版建议只进历史和摘要，不进入左右头像列。

建议第一版固定

  • 政治交易只支持当前会谈双方，不支持第三方绑定。
  • 交易最多 3 个不同罪行。
  • 交易接受后不可撤销，所有票来源标记为 trade。
  • 所有对话结束路径都先进入议会状态页，再回到 NPC 三选一。
最小可玩目标：第一章 4 人局中，玩家能看到 NPC 主动提出政治交易，确认后双方票同时落入状态页，并可能立刻触发处决。这就是本轮改进的硬验收。
